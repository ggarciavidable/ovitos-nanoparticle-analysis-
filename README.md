# OVITO analysis utilities for nanoparticle compression simulations

This repository contains small Python scripts developed for the post-processing of molecular dynamics simulations of diamond nanoparticles under indentation.

The scripts were originally written as research utilities for a specific simulation workflow rather than as a general-purpose software package. They are made available to facilitate reproducibility and reuse of the analysis procedures employed in the associated doctoral research.

## Requirements

* Python
* NumPy
* OVITO Python interface (`ovitos`)

The scripts were developed and tested using **OVITO 3.0.0-dev469**. Compatibility with later OVITO versions has not been systematically tested and minor API adaptations may be required.

## Scripts

### `equatorRadius.py`

Estimates the transverse radius of a nanoparticle during deformation from the atomic coordinates.

For each trajectory frame, atomic positions are projected onto the \(xy\) plane and their radial distances from the projected nanoparticle centroid are calculated. The script reports, among other quantities:

* maximum projected radial distance;
* mean radial distance of the outermost 1% of atoms;
* standard deviation of this outermost population;
* mean and standard deviation of the uppermost and lowermost 1% and 0.1% of atomic \(z\) coordinates.

These quantities are written as OVITO global attributes and can subsequently be exported as a table of values.

The outermost-percentile definition is an operational estimator designed for the nanoparticle geometries considered in the associated simulations.

### `strain-VergelesContactArea_ovitopyinterface.py`

Computes deformation and contact-area quantities for a nanoparticle compressed between planar indenters.

For each trajectory frame, the script determines quantities including:

* nominal compressive strain;
* indentation depth;
* indenter position;
* nanoparticle extent along the loading direction;
* upper and lower contact areas;
* effective contact radius;
* analytical contact area and radius for an ideal spherical geometry.

The atomistic contact area is calculated using the relation proposed by Vergeles et al. [1],

$$ A_c=\frac{2\pi}{N}\sum_{i=1}^{N} \left[(x_i-x_c)^2+(y_i-y_c)^2\right], $$

where \(N\) is the number of atoms identified as being in contact with the indenter and \((x_c,y_c)\) is the in-plane center of mass of those atoms. In the present implementation, contact atoms are operationally defined as atoms lying within a cutoff distance vergelesCutoff × a0 from the indenter plane. The default values correspond to vergelesCutoff = 0.25 and a0 = 3.567 Å and should be reviewed when applying the script to other systems.

By default, the script attempts to read relevant simulation parameters directly from a `log.diamond` or `log.lammps` file located in the same directory as the trajectory dump files. The parsing rules reflect the LAMMPS input conventions used in the original simulations and may require modification for other simulation setups.

## Usage in OVITO

These scripts were designed to be used through OVITO's **Python Script Modifier**.

1. Load the molecular-dynamics trajectory in OVITO.
2. Add a **Python Script Modifier**.
3. Load or paste the corresponding script.
4. Process the trajectory.
5. Select **File → Export File** and choose a **Table of Values** output.
6. Select the desired global attributes generated by the script.

## Scope and limitations

These utilities reproduce analysis procedures developed for a particular molecular-dynamics workflow. Several geometric assumptions, variable names, file conventions, and default parameters are therefore specific to those simulations.

Users applying the scripts to other systems should verify, in particular:

* the loading direction;
* indenter geometry and initial positions;
* units;
* timestep and indentation rate;
* lattice parameter;
* definition and cutoff used to identify contact atoms;
* LAMMPS log-file variable names.

The scripts are provided primarily for transparency, reproducibility, and adaptation rather than as a maintained general-purpose software package.
